# Coral-on-Black Stitch Skin and the Tab Band

Partially supersedes [ADR-0007](./0007-tab-shell-ui.md) (its visual language — acid-lime accent, Grizzlython ramp, its font contract), [ADR-0009](./0009-rail-hosted-chrome-and-inline-notices.md) (its chrome placement: the desktop rail-column grid with the Brand Unit as `col-span-4` first child no longer applies; the merged sticky block stays and is now the only mechanism at every breakpoint), and [ADR-0013](./0013-mix-tab-cohesion-and-the-single-playhead-readout.md) (only its Mix rail order claims meet a new visual language; its Playhead, one-clock and single-readout contracts survive untouched). Recorded 2026-11-04 as the record of the Stitch Skin increment (`.scratch/stitch-skin/spec.md`, tickets 01–07). Design source: the user's Google Stitch Mix-Tab mockup (`stitch.html` at the repo root, added 2026-11-04 by the override below) plus desktop/mobile screenshots; the OpenDesign MCP was NOT called for this increment (forbidden), so the look is recorded on the tickets as agent-authored via the documented dead-MCP fallback route.

## Decision

**The same Tab Shell, redone in the mockup's language: coral-on-black, rounded, Inter + JetBrains Mono, one sticky Tab Band at every breakpoint — and the mockup's phantom chrome rendered VERBATIM as dead placeholders until a cleanup commit erases them.**

The **Tab Band** is the whole chrome at every breakpoint: the **Brand Unit** row over the four Tab chips, one sticky block pinned while scrolling, no `<header>` element anywhere. The desktop vertical rail column and the two-block mobile split die; there is one responsive mechanism, not a drifting pair. Chips are compact JetBrains Mono at `TAB_CHIP_TYPE_PX = 11` px on `TAB_CHIP_MIN_TARGET_PX = 44` px targets; the active chip is a solid coral pill with the chip glow, gated chips grayscaled with their shipped reason line, `aria-disabled` intact.

Identity is the mockup's: coral rounded-square mark with a glowing inner diamond, mixed-case bold Inter wordmark, always-visible mono tagline — the uppercase DEMUXIFY lockup is gone. Every token moves through the existing architecture: a new named chrome ramp `st-*` replaces the grz ramp in the Tailwind config, the ink scale replaces default grays on surfaces, the radius retune sweeps the `rounded-none` utilities, and the mockup's Tailwind-CDN hex values are design source, never code to copy. Canvas marks retarget to the mockup's palette (electric lime trace, deep-black waveform box, coral Playhead glow) with the Beat Grid and waveform math untouched.

The **mockup is the DESIGN TRUTH** (user override, 2026-11-04): the running app must copy `stitch.html` at desktop and mobile, including the phantom controls the app never had — undo/redo/gear icons, an engine badge, a master transport bar with loop/seek/fast-forward/TAP glyphs and VU pips, a beat-dot and BAR counter, a 4/4 Beat chip, a phantom third DSP-rack card. Those render as DEAD PLACEHOLDERS: marked `data-mockup-placeholder="true"`, aria-hidden, built from DIVS only — no button roles, no handlers, no state — pinned by the guardrail as placeholder-only in `scripts/check-retired-affordances.mjs`, which exempts placeholder subtrees for exactly this drop list while the strict ban list (the grz family, the Downbeat axis, the Click-lane mute, the pill-slider, the header band, the faces) stays strict everywhere, placeholders included. A later cleanup commit erases the placeholders and returns the exemption to a hard ban.

## Why these trades

**Why the mockup, not a fresh design pass:** the user generated this mockup for the Mix Tab and asked for the app to wear it; it is a complete, coherent visual language (surfaces, hairlines, radii, chip glow, mono micro-type) that a hand pass would only dilute. The conversation that produced it is unreachable from any future session, so the increment's contract had to move the values into the token layer and the tickets, and `stitch.html` itself is now pinned in the repo as the design truth.

**Why placeholders for phantom chrome instead of dropping them:** the spec's original rule drops mockup controls with no shipped behavior, and that rule is what kept the app honest for tickets 01–06. The 2026-11-04 override asks for a verbatim copy of the mockup at both breakpoints — refused, every screenshot comparison fails. The placeholder contract makes "dead" mechanically true (divs, aria-hidden, no handlers, no accessible names on the chrome, the four Tab buttons keep theirs) and makes LIVE revival red at the gate, so the exemption cannot spread beyond the drop list it names. The cleanup commit is the recorded way back.

**Why 11px chips on 44px targets:** the mockup's chrome is denser than the shipped one, but touch targets and screen-reader reachability are interaction contracts (spec Out of Scope) — the type shrinks, the hit area does not, and both numbers become named consts so the ADR cannot drift from code.

**Why the Tab Band keeps one mechanism at md+:** ADR-0009's lesson — a desktop/mobile chrome pair reintroduces the drift it removed. Same sticky block, same pinned scroll unit, same four chips at every width; only inner flow changes (stacked under `md`, side-by-side above it).

## Considered Options

- Drop the phantom controls per the original spec rule (rejected by the 2026-11-04 override: the user wants the verbatim mockup; kept as the recorded cleanup target).
- Render phantom controls as real buttons wired to nothing (rejected: dead chrome must not carry button roles, accessible names, or focus contracts — it would lie to both the a11y tree and the test suite's chrome counts).
- Ban the phantom vocabulary strictly everywhere including placeholders (rejected: the verbatim requirement itself would fail the gate; the exemption is scoped to placeholder subtrees only, proven both ways when the gate classifies the three placeholder regions green and a live 0 dB line red).
- Re-tune the existing grz ramp through CSS-variable values instead of a new `st-*` ramp (rejected: class semantics would lie — surfaces named grz-02 wearing coral-black — and the rounded-none sweep plus the ink scale would fight default-palette survivors).
- Call the OpenDesign MCP for the skin (rejected this increment: the run is forbidden for the effort; the agent-authored fallback is recorded on every ticket per `docs/agents/open-design-mcp.md`).
- Keep the desktop rail column and restyle it (rejected: the mockup's chrome is a sticky top band; keeping both mechanisms is the drifting-pair pattern ADR-0009 killed).

## Hard to Reverse

The three placeholder subtrees — the Tab Band's phantom cluster, the footer's master transport bar, and the DSP rack's third card — are dead contracts: `data-mockup-placeholder="true"`, aria-hidden, DIV-only, and the guardrail's PLACEHOLDER_EXEMPT list is their only exemption. Removing the markers without removing the markup goes red; so does any drop-list pattern outside a placeholder subtree. The strict list keeps its teeth inside placeholders: no grz class, no Downbeat symbol, no Click-lane mute, no pill-slider trio may hide behind a placeholder either. The chip template interpolates `TAB_CHIP_TYPE_PX = 11` and `TAB_CHIP_MIN_TARGET_PX = 44`, so the recorded anchors and the rendered chrome cannot drift apart; radii stay prose pointers to the config's radius scale.

## Supersede

Partially supersedes [ADR-0007](./0007-tab-shell-ui.md): the Tab Shell frame, four-Tab gating and the port-through-React process stay; its acid-lime accent, Grizzlython ramp, Wayback font contract and zero-radius chip claims no longer apply. Partially supersedes [ADR-0009](./0009-rail-hosted-chrome-and-inline-notices.md): the merged sticky block, the dead page-level header, the inline-notice pattern and the flat hairline footer cap stay; the rail-column grid, its desktop-only tagline, and the Tab Rail phrasing are retired — the glossary names the **Tab Band** and files **Tab Rail** as _Avoid_. Partially supersedes [ADR-0013](./0013-mix-tab-cohesion-and-the-single-playhead-readout.md) for visual language only: its one-Playhead, single-readout and rail-order contracts survive and this increment re-wears them rather than re-ordering them. It resurrects nothing the [ADR-0010](./0010-client-side-tempo-detection-and-click-track.md)/[ADR-0011](./0011-downbeat-reading-and-beat-grid-repair.md) Amendments retired — the mockup shows a metronome card, beat counters and a BAR readout that contradict the uniform Click Track: the guardrail wins, and those stay dead outside the recorded placeholders.
