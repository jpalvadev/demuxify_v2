Problem

Every engine fact the shell shows is mirrored a second time: play-state, peak levels, master volume, and the Playhead cross the Stem Player interface as four channels, land in three App states plus a mutable ref assigned during render, and the footer JSX reads the mirrors. Understanding "what the footer displays" bounces across three modules — and this wiring is the repo's hot zone (every stitch-skin footer commit edits it).

Solution

One Transport module (the glossary's name for the row that acts on position) sits at the shell seam: live adapter subscribes the engine's existing channels once and exposes one snapshot + four commands; App keeps no mirror states; footer, spine, and readout read the same snapshot. A scripted adapter replaces the App-seam AudioContext swapping tests.

  • locality: footer-fidelity work lands in one module
  • leverage: one snapshot, all shell readers
  • mutable ref + 3 mirror states deleted
  • tests hit the snapshot interface, not full App render
  • ADR-0013 channels keep their meaning — cadence rules move inside the implementation, not the interface
ADR note: respects ADR-0013's rejected "per-frame mixer bridge" — the snapshot must feed on the existing single position channel, and the mixer bridge keeps its save cadence inside the module.

Problem

  • the interface is the test surface: fake worker tests the full flow
  • five call sites shrink to five verbs
  • stale-closure patch deleted — stems arrive as a parameter
  • leverage: re-lock, calibration, resume share one implementation

3 · Deepen the Session: factory, restore, record, purge in one place

Strong in-process

Problem

  • locality: the §2 violation disappears with its one call site

  • restore tested headless — no AudioContext swapping
  • leverage: recovery, resume, purge share one shape

Problem

The deep encoding modules (customMixdown, wavEncoder, mp3Encoder, bundleZip) are assembled by a UI module: the choreography — render order, progress arithmetic, four cancel checkpoints, filename rules — is untestable glue, and the suite documents the stall with a spy workaround. The Export pipeline has no interface of its own.

Give the pipeline a module: renderExport accepts stems + export config, returns {blob, fileName}, reports progress, obeys an AbortSignal. The dialog keeps the controls and subscribes; download triggering stays with the DOM.

  • locality: cancel + progress arithmetic in one module
  • leverage: Export Tab panel and any future surface share one render
ADR note: ADR-0008's inline Export panel fed through the Transport bridge stays exactly as recorded — the panel is the caller, the pipeline moves behind its own seam.

Problem

The engine's implementation is deep (worklet, WSOLA, fallback sources, click synthesis), but its interface is shallow: ~35 thin get/set/toggle methods and four subscribe channels. StemPlayer re-mirrors nearly every fact into React state, and callers must learn the full method map to touch playback at all.

Solution

Collapses the pairs: partial-state commands in, one snapshot out, one subscription. Toggle semantics (ADR-0012's per-Stem solo/mute exclusivity) move inside the module where the gain matrix already enforces them.

  • leverage: 35-method map → 8 verbs at the seam
  • StemPlayer's mirror states shrink with the interface
  • speculative: 42 tests pin the current surface — do C1 first, it lowers the blast radius

Pass-through detritus (fold into any commit that touches these files)

  • src/components/StemTrack.tsx — a 3-line re-export of StemStrip for "backwards compatibility" with zero importers. Deletion test: complexity vanishes entirely. Delete it.
  • formatTime (StemPlayer.tsx:124) vs formatTransportTime (App.tsx:112) — one mm:ss formatter typed twice, already drifting (NaN clamp in one, floor in the other). Fold into one utility before the drift becomes a visible clock disagreement.
